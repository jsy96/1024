# 颐养通

面向居家养老服务公司的社区养老协同产品。社区负责公司签约入驻、高龄老人资格核定和虚拟补贴发放；老人自主选择签约公司的服务员；上门服务留下地址打卡与结束合影，订单和账本共同构成社区与公司、公司与员工的结算依据。

**只向养老服务公司收取平台使用费，个人与社区免费使用平台。** 老人的服务消费使用内部虚拟货币「服务币」，平台免费使用不等于上门服务免费。

本仓库提供 **Mac / Windows 本地演示**，默认访问 `http://127.0.0.1:8000`。仓库地址：<https://github.com/jsy96/1024.git>。

## Mac / Windows 启动

### macOS

需要 Python 3.9 或更新版本。双击 [启动本地.command](启动本地.command)，或在项目目录执行：

```bash
bash 启动本地.command
```

首次启动自动创建 `.venv-mac` 并安装 `requirements.txt`。如果 macOS 不允许双击，使用上面的终端命令即可。启动后浏览器会打开本地页面；按 Control+C 停止。

### Windows

需要 Python 3.9 或更新版本。双击 `start_windows.bat`，或在项目目录执行：

```bat
start_windows.bat
```

脚本会优先使用 `py -3`，没有时回退到 `python`；首次启动自动创建 `.venv-win` 并安装依赖。安装 Python 时需要勾选 `Add Python to PATH`。首次安装依赖需要联网，启动后浏览器会自动打开本地页面。

手动方式：

macOS：

```bash
python3 -m venv .venv-mac
.venv-mac/bin/python -m pip install -r requirements.txt
.venv-mac/bin/python server.py
```

Windows：

```bat
py -3 -m venv .venv-win
.venv-win\Scripts\python.exe -m pip install -r requirements.txt
.venv-win\Scripts\python.exe server.py
```

两个平台都只监听 `127.0.0.1`。数据保存在 `data/care-mac-demo.db`，与线上数据库独立。已存在的本地旧版 SQLite 数据会增量迁移，保留订单和流水；旧订单若缺少打卡与合影，不进入新的凭证结算。

## 可用服务

### 社区：签约、补贴、核账

- 登记养老公司及公司管理员，记录合同编号、起止日期；终止以独立事件保存原合同。
- 管理本社区老人档案，核定高龄补贴资格；停用人员会保留历史。
- 按业务批次给符合资格的老人发放服务币补贴；也可按充值凭据记录服务币充值。每笔都有编号、依据、操作人和服务器时间。
- 原始入账不可改写，出错时填写原因追加冲正；同一业务批次不得再次发放。余额不足时阻止扣减冲正。
- 查询本社区订单、打卡、合影、充值与消费流水，按记账日期生成社区与公司结算依据及 CSV。
- 已完成订单由社区核实退款，原服务流水保留，追加退款与负数结算调整。

### 老人：跨公司自主选人

- 选择社区签约公司，再选择该公司的服务员和服务项目，无固定绑定。
- 按服务币时薪和预约时长报价，订单保存价格与酬金快照。
- 预约日期核对合同，校验工作时段、服务员冲突和路途缓冲。
- 未完成预约占用可预约额度；服务完成时实际扣款，避免多张预约重复使用同一额度。
- 查看自己的订单、打卡、结束合影、余额和逐笔服务币变动；未开始的预约可取消。

### 服务员：上门留痕

- 确认上门，查看预约地址、上报异常；未开始的订单可改期并重新确认。
- **开始服务前**，浏览器获取实际位置（WGS84 经纬度和精度），服务员填写实际打卡地址，服务器记录时间。仅允许当天订单打卡。
- **结束服务后**，上传与老人的合影并确认已征得同意。有效打卡和有效图片缺一不可；完成时一次性扣款并生成结算条目。
- 图片支持 JPG / PNG / WebP，最大请求 8MB；校验解码、尺寸，转为去除原始元数据的 JPEG，保留 SHA256。凭证只对订单相关角色开放。
- 查询本人酬金核算批次及导出明细。
- 按预约时间估算行程，保留路途、午餐、天气和电量提醒；地图与天气需联网，未配置地图 Key 时使用距离估算。

### 养老公司：管理与酬金依据

- 管理本公司员工、服务项目、服务币时薪、默认服务时长与员工酬金核算单位。
- 仅可访问本公司的订单、服务消费和结算记录。
- 查询社区合作合同，处理改期、取消和异常服务。
- 按员工、记账日期预览酬金，确认生成批次，导出带订单与凭证编号的 CSV。

## 下一步扩展

- 普通顾客可直接预约并线下自行结算，不发放、不使用服务币，也不进入老人补贴账本。
- 服务员可生成分享名片，展示服务项目、可预约时间与累计履历，让优秀的一线服务员被更多顾客看见。
- 按订单向相关顾客展示已授权的预约、出发、打卡、完成等服务进度；公开名片与私人履约信息分别控制访问范围。
- AI 在后台辅助路线、天气、午餐、电量、服务摘要和异常提示，让平时不熟悉 AI 的服务员只用手机也能获得帮助。
- 提前一天的行程推送、评价规则和公开范围仍需通过真实试点确认，目前是产品扩展方向，不声称已经上线。

居家上门服务与一般到店服务不同：服务员进入老人私人家庭，产品必须围绕老人授权、家属联系、现场安全、隐私保护和长期信任设计。技术记录不能替代社区和公司的身份核验、紧急救助与人工复核。

## 账本与结算规则

- 内部金额以百分之一服务币整数存储。服务币与实际人民币的兑付规则由社区、公司签订的合同确定，系统不假定固定兑换比率。
- 社区与公司按服务币消费净额核对；公司与员工按预约时固定的酬金单位核算。实际酬金兑付规则另行约定。
- 原始账本、合影凭证、操作日志、合同及合同事件、结算条目和结算批次受 SQLite 触发器保护，只能追加。
- 每笔完成订单产生一条服务消费及两层结算条目；退款追加一条负数调整，可在后续批次抵扣。
- 两层结算分别防重；生成结算时核对预览的条目集合，避免过期页面误计入新订单。
- 生成的是 **结算依据**，并不代表已经收款、银行转账或发薪；系统没有真实支付、充值收单、订阅扣费功能。
- 定位与合影是提交的凭证，系统不能自动证明服务真实发生、识别人脸或核验合影时间。社区和公司需人工核验，演示图片不会作为真实履约证明。

## 技术与配置

Python + Flask + SQLite，前端为原生 HTML / CSS / JS，Leaflet 已随仓库提供，无前端构建步骤。主功能不需要外部数据库或云账号。

`config.json` 配置工作时段、冲突缓冲、地图中心和行程参数。可选 `AMAP_KEY` 环境变量，或在忽略的 `secrets.json` 中设置 `amap_key`，增强骑行路线；不填不影响预约、凭证及账务。浏览器定位另需在 Mac 系统设置和浏览器中允许位置权限，定位失败会明确提示，不伪造坐标。
